# Repository-name
你是一个资深 Python 工程师，需要开发一款无数据库、无服务端、无 GUI的纯本地定时天气获取小程序，严格遵守文件拆分、路径、格式、命名等强约束，仅聚焦文件处理、定时任务、数据解析与本地日志存储逻辑，完成可直接运行的轻量化工具开发。
任务描述
开发 Python 定时天气获取小程序，支持配置指定城市、定时执行频率，自动通过公开天气接口获取实时天气数据，将数据格式化保存为本地文件，并生成运行日志；程序全程无交互、无 GUI、无网络服务端、无数据库，纯本地自动化运行，严格遵守所有强约束条件。
功能需求
支持通过配置文件自定义目标城市、定时执行间隔（分钟）、接口请求超时时间
使用公开免费天气 API（无需密钥）获取城市实时天气（温度、天气状况、湿度、风向、更新时间）
定时任务自动循环执行，程序启动后后台持续运行
每次获取成功后，将天气数据按固定格式写入本地输出文件
全程记录程序运行日志（启动、执行成功、请求失败、配置错误等）
异常自动捕获（网络错误、城市不存在、接口异常），不中断程序运行
强约束条件
文件夹路径约束：输入配置文件必须存放于 ./config/ 目录，天气数据输出文件必须存放于 ./data/output/ 目录，日志文件必须存放于 ./logs/ 目录，程序仅允许使用相对路径，禁止使用绝对路径
文件格式约束：配置文件必须为 .yaml 格式，天气输出数据必须为 .json 格式，日志文件必须为 .log 格式
命名规范约束：所有自定义函数必须使用 snake_case 命名法，所有常量必须全大写 + 下划线命名，所有生成的天气数据文件名必须以 weather_ 开头 + 8 位日期（如 weather_20260402.json）
不可修改区域约束：./config/ 目录下的 default.yaml 为默认配置模板文件，程序仅允许读取，禁止修改、覆盖、删除该文件
文件结构要求（必须拆分 6 个独立文件）
main.py：程序入口，启动定时任务、初始化所有模块
config_loader.py：加载并解析 YAML 配置文件，校验配置合法性
weather_fetcher.py：调用天气 API，获取并解析原始天气数据
data_saver.py：格式化天气数据，按约束写入指定路径的 JSON 文件
task_scheduler.py：实现定时循环任务，控制执行频率
logger_util.py：统一日志管理，按约束写入日志文件
